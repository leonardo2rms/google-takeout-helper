## 0. Decisions in one screen

| Topic | Decision |
|---|---|
| Concept | An engineer's drafting sheet, with a "blueprint" dark mode. Ink on cool paper, hairline rules, mono for labels and numbers. Verdicts work like **code-review marks** (a rail, a squiggle, a label), not like game feedback. |
| Palette (8 base tokens) | `paper #F2F4F6`, `ink #0F1B26`, `graphite #4A5967`, `edge #7B8996`, `cobalt #2447C4`, `teal #00695F`, `vermilion #AE320C`, `ochre #8A5300`. Dark: `#0D1721 / #E7EDF2 / #9DADBB / #62758A / #86A6FF / #46D2B8 / #FF8F6B / #EBB650`. |
| Primary action | Solid **ink** button (not green). The only saturated colours left on screen are verdict colours and one cobalt for "interactive". |
| Verdicts | Teal = correct, vermilion = incorrect, ochre = partial, cobalt = selected/info. Every verdict also has an **icon + word + border style**. Colour alone never carries meaning. |
| Type | One embedded variable face: **IBM Plex Sans** (OFL), Latin subset, 23 kB woff2. Plus the **system mono** stack for code, labels and numerals. |
| Shape | 6px radius controls, 10px panels, 3px chips. **No pill shapes, no chunky bottom borders, no drop shadows.** 1px "edge" outlines. Pressed state is a background shift. |
| Icons | 23 inline-SVG icons from **Lucide** (ISC licence), 1.75px stroke, about 3.1 kB total. Emoji removed everywhere. |
| Home | The zig-zag path becomes an **index of lessons** (title block per unit, 56px rows). About 35% shorter per unit and much denser. |
| Feedback | Neutral sheet panel with a 4px verdict rail, a mono verdict line (icon + word), ink body text. No pastel fills, and no text coloured by verdict. |
| Summary | No trophy emoji. A mono "result readout" (big percentage plus a ruled table). |
| Cost | Roughly +40 kB on the 522 kB single-file HTML (font about 31 kB as base64, icons 3 kB, CSS about 4 kB). A zero-byte fallback is described in 3.2. |

## 1. Critique of the current UI

### 1.1 What reads as generic / AI-generated / Duolingo clone

Seen in the screenshots and `web/src/styles.css`:

1. **The palette is Duolingo's, almost to the hex.** `#58cc02` green, `#ff4b4b` red, `#1cb0f6` blue, `#ff9600` orange, `#ffc800` yellow, `#ce82ff` purple, `#131f24` dark ground. The eight unit banners are each a different saturated hue with white text on top. It is the most recognisable "template" in the app, and the main reason the product looks cloned.
2. **Chunky 3D buttons everywhere.** `border-bottom-width: 4px` on `.btn`, `.option`, `.chip`, `.card`, `.match-item`, `.key`, plus 6px hard shadows under the round nodes. Every control has the same 16px "pill-ish" radius, so there is no hierarchy between a primary button, an answer option and a tag.
3. **Emoji as the icon system.** Fire, lightning, dice, bandage, puzzle, spool, leaf, coffee, classical building, robot, "offline" phone, microphone, trophy, target, sparkles, compass. Emoji render differently on every OS (see the 3D-looking puzzle piece in `home-light.png`), cannot take a theme colour, and signal "consumer game". They are also used as semantic markers, which is fragile.
4. **Centred emoji "trophy" on the Summary** (84px, pop-in animation) followed by "Lesson complete!" and three coloured tiles. This is the stock AI layout for a results screen.
5. **Pastel feedback panels with coloured body text.** The whole explanation paragraph is red-on-pink, green-on-mint or brown-on-cream. It is hard to read, fails contrast in places (see 1.2), and the long technical explanations are the most valuable content in the app.
6. **Cheerleading copy.** "Nice one!", "Spot on!", "Well done!", "Perfect lesson!", "Keep going!", chosen randomly. Senior engineers read this as condescending.
7. **system-ui only.** There is no typographic voice. Bold 800 weight with uppercase tracked labels on every button ("CHECK", "I DON'T KNOW", "CONTINUE") adds to the toy feel.
8. **Zig-zag lesson path.** Round nodes at alternating indents. It is a decoration borrowed from a language-learning app and wastes a lot of a 390px width. Two lessons per unit take about 330px of vertical space.
9. **Rainbow of verdict, selection and unit colours.** Blue means "selected", but the same blue is the secondary button, the link and "Next lesson". Green means correct, but also "primary button", "accuracy" and the default unit colour. Colour has no stable meaning.
10. **Red/green as the only verdict signal.** After checking, an option differs only by border colour and tint (the "missed" option is a dashed green border). There is no icon and no text (and no screen-reader text either). It is unsafe for red-green colour blindness (about 8% of men).

Usability problems found while reading the code (fix during the restyle):

| Where | Problem |

| `.src-line` (spot the bug) | Rows are about 28px tall, below the 44px target. |

| `Feedback.tsx` `'→'`, `'✓'`, `'✗'`, `'↻'`, `'●'` | Text glyphs used as icons. They fall back to random system fonts. |
| Match pair colours | Six hues including `#ff4b4b` (looks like "wrong") and `#58cc02` (looks like "right"), identifiable only by hue. |

## 2. The identity: "Drafting sheet" (light) and "Blueprint" (dark)

### 2.1 Concept

A senior engineer's notebook and technical manual, not a game:

- **Ink on cool paper.** Text is a blue-black ink, never pure black. The page is a faintly blue-grey sheet (`#F2F4F6`), raised elements are a lighter sheet (`#FBFCFD`). Dark mode is the same drawing as a blueprint: deep navy ground, light-ink lines.
- **Hairline rules, title blocks, index tables.** Units become title blocks of an engineering drawing set ("UNIT 03", numbered lessons "3.1", "3.2"), progress becomes a **gauge with a tick per question**, results become a **ruled readout**.
- **Mono for measurement.** Numbers (XP, streak, counters), kickers, test output and tags use a mono face with tabular, slashed-zero figures. Prose uses a sober grotesque.
- **Verdicts as review marks.** Correct: a teal rail and a check. Incorrect: a vermilion rail, a cross and a **wavy "diagnostic" underline** (the same squiggle code editors draw). Partial: a dashed ochre rail and a half-filled circle. It reads like feedback in a code review.
- **Deliberately absent:** neon-on-black, cream-paper plus serif plus terracotta, purple gradients, glassmorphism, glow, confetti, emoji, mascot.

Differentiator in one line: *the app looks like the tools its users already trust (editor, PR review, test runner), set with print-manual discipline.*

Other rules, all verified:
- `ink` on every tint is at least 12:1 (light) and 10:1 (dark). **Body text on verdict panels is always ink.** Verdict hue is only used for icon, label, rail, border and underline.
- Solid-filled markers (selected, correct, wrong) put the **`paper`** colour on the verdict colour. That is automatically the right polarity in both themes (white on dark cobalt, dark on light cobalt). Ratios: 5.7 to 9.8.
- Primary button: `paper` on `ink`, 15.8 (light) / 15.3 (dark). In dark mode the primary button is a light slab, which is the strongest affordance on screen.
- Disabled primary: `graphite` on `hairline`, at least 3:1 (WCAG exempts disabled controls, but it stays legible).
- Focus ring: `2px solid cobalt` plus 2px offset. Cobalt vs paper is 6.87 / 7.67, comfortably above 3:1 on every surface.
- Contrast was checked with every pairing the UI uses: 156 checks in `verify.md`, 0 failures. `check-contrast.mjs` runs 176 pairings against the final CSS.

### 2.3 Semantic colour system (colour-blind safe)

Rule: **a verdict is always expressed by at least three of: icon, word, border style, underline style, hue.** Hue is the weakest channel.

| State | Hue | Icon (Lucide) | Word | Border / rail | Text-level mark | Used on |
|---|---|---|---|---|---|---|
| Correct | teal | `check` | "Correct" | solid 1px + 1px inset (2px look), 4px solid rail on panels | none | option, blank, order row, spot line, match item, test row, feedback |
| Incorrect | vermilion | `x` | "Incorrect" | solid 2px look, 4px solid rail | **line-through** on the option text; **wavy underline** on code (blank, order row, spot line) | same |
| Partial | ochre | `contrast` (half-filled circle) | "Partial 2/3" | **dashed** 4px rail | none | open-answer feedback, follow-up mix |
| Missed answer ("this was the right one") | teal, outlined | `check` in a dashed circle | "Answer" | **dashed** teal border | none | option, spot line |
| Selected (pre-check) | cobalt | filled marker with check or dot | none | solid 2px look in cobalt | none | option, match item, blank, spot line |
| Info / interviewer | cobalt | `message-square-quote`, `info` | label text | 4px rail on `cobalt-tint` | none | follow-up note, "Up next" |

Colour-blind simulation (Machado 2009, full severity, CIE76 ΔE between the colours as rendered; full table `cvd.md`):

| Pair | Normal | Protan | Deutan | Tritan |
|---|---|---|---|---|
| Old: `#ff4b4b` vs `#58cc02` | 133 | 58 | 20 | 126 |
| Old feedback text: `#c0392b` vs `#3d7f00` | 94 | 29 | **4** | 100 |
| **New light** teal vs vermilion | 92 | 39 | 55 | 100 |
| **New light** teal vs cobalt | 92 | 68 | 68 | 19 |
| **New light** vermilion vs cobalt | 118 | 106 | 122 | 98 |
| **New dark** teal vs vermilion | 90 | 27 | 43 | 100 |

Teal (blue-green) versus vermilion (orange-red) separates on the blue-yellow axis, which protan and deutan users keep. Two known weak spots, and how they are covered:
- Vermilion vs ochre are close for protan/deutan (ΔE 3 to 7 in light). They never appear together as the only cue: partial has a different **icon** (half circle vs cross), **word** ("Partial") and **dashed** rail instead of solid.
- Teal vs cobalt are close for tritan (ΔE about 19). "Selected" and "correct" never co-exist in the same state, since checking replaces selected with a verdict, and the verdict adds icon plus word.

Screen readers: today states are conveyed only by CSS class. The redesign adds a visually-hidden or visible text for every verdict (see 8.4, `StateMark`).

### 2.4 Unit "pens" (wayfinding, not decoration)

The eight unit hues from content are no longer used. Instead, each unit gets a muted "pen" colour used in exactly two places, a 3px spine on the unit head and the glyph outline. Text on the unit head is always `ink` / `graphite`, so contrast failures cannot occur.

All eight pen values sit in the luminance band 0.18 to 0.20, so **one value works in both themes** (at least 3.67:1 against paper and sheet, light and dark):

## 3. Typography

### 3.1 Faces (two, maximum)

| Role | Face | Delivery |
|---|---|---|
| Prose, prompts, headings, buttons | **IBM Plex Sans**, variable `wght` 100 to 700 | self-hosted, Latin subset, embedded |
| Code, kickers, numerals, tags, test output | **System mono** (`ui-monospace, "SF Mono", SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace`) | no bytes |

Why Plex Sans: technical-manual heritage, characterful letterforms (angular terminals, distinctive `a`, `g`, `r`), tabular-friendly digits, designed for dense UI. It is not on the "AI default" list (Inter, Space Grotesk, Geist). It reads well at 14 to 16px on a phone. Licence: SIL OFL 1.1 (bundle the licence text).

### 3.2 Packages, subsets and byte budget

Measured in the scratchpad (npm pack of `@fontsource-variable/ibm-plex-sans@5.3.0`, subset with fontTools 4.68):

| Option | woff2 | As base64 in the single HTML | Notes |
|---|---|---|---|
| **A (recommended): custom Latin subset of the fontsource file** | **22.9 kB** | about 31 kB | Axes: `wght` 100 to 700. 112 glyphs. |
| B: fontsource file unmodified (`files/ibm-plex-sans-latin-wght-normal.woff2`) | 45.7 kB | about 61 kB | No tooling step. |
| C: zero bytes, system stack only | 0 | 0 | See fallback below. |

Option A recipe (run once, commit the output; the build does not need Python):

```bash
npm i -D -w web @fontsource-variable/ibm-plex-sans@5.3.0     # source of truth for the subset only
pip install fonttools brotli
pyftsubset node_modules/@fontsource-variable/ibm-plex-sans/files/ibm-plex-sans-latin-wght-normal.woff2 \
  --unicodes="U+0020-007E,U+00A0,U+00B7,U+00D7,U+2013,U+2014,U+2018,U+2019,U+201C,U+201D,U+2022,U+2026,U+2192,U+2190,U+2191,U+2193,U+2264,U+2265,U+2248,U+00B2,U+2212" \
  --flavor=woff2 --layout-features='kern,liga' \
  --output-file=web/src/fonts/plex-sans-var-latin.woff2
```

Notes:
- Characters absent from the fontsource Latin file (`→ ≈ √ ₂ ⁿ λ` appear a few times in `content/*.yaml`) fall back to the system font automatically. That is acceptable and invisible at prose size. `Feedback.tsx` should use the `arrow-right` icon instead of a literal `→` (8.4).
- Budget: **the font may not exceed 25 kB of woff2** (about 34 kB base64). The single-file HTML goes from 522 kB to about 560 kB in total with icons and the larger stylesheet. If a hard 500 kB ceiling matters, use option C.
- Option C, system-only fallback tuned for character: `--sans: ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;` and apply `font-weight: 600` (not 800), `letter-spacing: -0.01em` on headings, kickers in mono. About 70% of the identity survives, since most of it comes from palette, mono labels, rules and shapes.
- `@font-face`:
  ```css
  @font-face { font-family: "Plex Sans Var"; src: url("./fonts/plex-sans-var-latin.woff2") format("woff2");
               font-weight: 100 700; font-style: normal; font-display: swap; }
  ```
- Standalone build: `build-standalone.mjs` requires exactly one JS and at most one CSS file in `assets/`. A woff2 above Vite's 4 kB inline limit would be emitted as a separate file and be missing from the single HTML. In `web/vite.config.ts` use the function form of `defineConfig` and set `build.assetsInlineLimit: mode === 'standalone' ? 100_000 : 4096`. The font then becomes a `data:` URI inside the CSS, which `build-standalone.mjs` already inlines.
- Normal build and PWA: the font is a hashed same-origin asset. `sw.js` already does stale-while-revalidate on same-origin GETs, so it works offline after the first load. Bump `CACHE` to `interview-trainer-v2` so returning users do not keep the old CSS.
- No italic and no second weight axis are shipped. `<em>`, if it appears in content, is synthesised. The content is checked for none today.

### 3.3 Type scale (mobile first, 16px root)

| Token | Size / line-height | Weight | Face | Used for |
|---|---|---|---|---|
| `--t-label` | 12px / 1.2, tracking .08em, uppercase | 500 | mono | kicker, tags, tallies, stat labels (min 10.5px for the stat caption) |

## 4. Spacing, radius, borders, elevation

Spacing is a 4px scale: `--s1 4`, `--s2 8`, `--s3 12`, `--s4 16`, `--s5 24`, `--s6 32`, `--s7 48`. Page gutter 16px (unchanged). `#root` stays `max-width: 640px`.

Radius (a three-step scale, "full" only for dots):

| Token | px | Use |
|---|---|---|
| `--r1` | 3 | inline code, tags, checkbox squares, pair badge |
| `--r2` | 6 | buttons, options, inputs, code blocks, chips, rows |
| `--r3` | 10 | unit sections, bottom sheet |
| full | 50% | single-choice radio marker only |

Borders and elevation:
- **Controls: 1px `--edge` outline** (3:1 or better). State is shown by swapping the colour and adding `box-shadow: inset 0 0 0 1px <colour>`, giving a 2px look **without layout shift**.
- **Panels: 1px `--edge`**, plus a 4px left rail for verdict panels (the rail is the "mark").
- **Dividers inside a container: 1px `--hairline`.**
- **No drop shadows, no blur, no gradients.** The only "elevation" cues are the lighter `sheet` over `paper` and, in dark mode, the lighter sheet. The fixed bottom bar gets a hairline top and a 3px verdict-coloured inset stripe on `.good`/`.bad`.
- **Pressed:** background goes to `--hairline` (secondary) or `--graphite` (primary). No translate, no border-width change.
- Desktop (optional, cheap): behind `#root` use a slightly darker "desk" colour on `html` (`#E9ECEF` light, `#0A121A` dark, as extra tokens) and give `#root` `border-inline: 1px solid var(--hairline)`, so the app reads as a sheet on a desk.

## 6. Motion

Principles: motion explains a state change and nothing else. It is short, ease-out, and never bouncy.

| Event | Spec |
|---|---|
| Press (button, option) | background colour change only, 80ms |
| Selection / verdict colour change | 120ms colour/border transition |
| Feedback panel enters | `opacity 0 to 1` and `translateY(4px) to 0`, 160ms, `cubic-bezier(.2, 0, 0, 1)` (replaces the 8px `rise`) |
| Progress gauge | width transition 200ms ease-out; ticks are static |
| Check mark in marker | optional: `stroke-dashoffset` draw, 120ms |
| Summary readout | no pop, no scale. The number is simply present (optional: 150ms opacity) |
| Removed | trophy `pop`, 3D press-down `translateY`, node bounce |

Reduced motion:
- Keep the global rule (`animation: none !important; transition: none !important` under `prefers-reduced-motion: reduce`). Opacity-only fades are allowed to remain but the global kill switch is simpler and safe.
- **Also fix JS scrolling** in `Lesson.tsx`: `scrollIntoView({ behavior: window.matchMedia('(prefers-reduced-motion: reduce)').matches ? 'auto' : 'smooth', block: 'nearest' })`.
- Haptics and sounds: none.

## 12. Risks and open questions

- **Size.** Even option A adds about 40 kB to a file already at 522 kB. If 500 kB is a hard host limit, today's build already exceeds it; pick option C (system fonts) or shrink the JS separately.
- **Letters on options (A to D)** are an addition, not a requirement. If they feel too "exam-like", keep the empty marker and remove `.letter`; everything else in 8.5 stands.
- **Unit colours in YAML** become dead data. A follow-up could let content authors pick an icon id instead (`icon: braces`) and drop `emoji`/`color`.
- **Vermilion vs ochre** are close under protan/deutan (ΔE 3 to 7). The redundancy (icon, word, dashed rail) is mandatory. Do not drop the verdict line to save space.
- **`color-mix` / `inset box-shadow` / wavy underline** are supported on current iOS Safari (16.4+) and Chromium. The tints are shipped as explicit hex, so `color-mix` is not required anywhere in the new CSS.
- **Mono face varies by OS** (SF Mono, Menlo, Consolas, DejaVu/Liberation). Widths differ slightly; the layout never relies on exact mono widths (`overflow-x: auto` on code, `overflow-wrap: anywhere` elsewhere).

## Appendix B: how the numbers were produced

- `audit-current.mjs`: reads the old hex values from `styles.css` and the unit colours from `content/*.yaml`, blends alpha overlays, and reports 56 pairings per theme (39 and 25 failures).
- `verify.mjs` + `palette.mjs`: checks the new palette (156 pairings, 0 failures); `check-contrast.mjs` is the version meant for the repo (176 pairings against CSS).
- `cvd.mjs`: Machado et al. 2009 matrices (protan, deutan, tritan, severity 1.0) in linear RGB, then CIE76 ΔE.
- `pens.mjs`: searched HSL lightness for relative luminance 0.19 per hue, then confirmed at least 3.67:1 on paper and sheet in both themes.
- Font sizes: `npm pack @fontsource-variable/ibm-plex-sans@5.3.0` (latin `wght` 45,712 bytes; subset 22,948 bytes), `@fontsource-variable/archivo` (34,928, rejected as too display-oriented), `@fontsource-variable/jetbrains-mono` (40,404, rejected: code only, system mono is free).
- All scripts live in the scratchpad; none was added to the repo.
